修订日期：2026-10-06。基于远端 `main=f3d9d3b59525efff372f3d60d3982ff2b09a545b`。

## 结论与适用范围

保留 V2 的大路线：**用户认可的人物方向 → 确认具体参考 → 分镜关键帧 → 批准后 I2V → 静动态混剪 → 人工终审**。本次 V5 指制作数据与工具版本，不是换视频模型，也不是从头建设另一套框架。

本次用户要求是把非本地工作继续做细。因此已经把工作推进到：真实素材打包与哈希、30 个镜头的帧级计划、EP001 连续性和声音表、严格的提交前检查、可运行离线测试、可用的审片序列。**没有启动用户电脑、没有使用用户显卡、没有把“写了代码”称作“本机生成视频通过”。**

“建模”在当前主路线中是二维角色设计与参考资产，不是已经训练好的 LoRA，也不是可绑定骨骼的 `.blend/.fbx/.glb`。三维几何、拓扑、骨骼、贴图和训练权重目前没有交付，不把生成设定板的多视图当成几何一致性证明。

## 分阶段执行：每步输入、动作、产物与停止条件

### PREP-A｜导入已有素材，不再让用户重新寻找已经生成的图

输入：本次 `AI_short_drama_preproduction_v5.zip`；其中 `local/references/generated/20261005_v5/` 已包含真实文件。

动作：解压到一个临时目录，运行 `import_reference_bundle.py`，先检查全部 hash，目标已存在同 hash 文件就跳过，存在不同文件就报错，禁止覆盖。本工具不改批准状态。

产物：17 个已核实素材在本机同一相对路径下。3 张板为 `MODEL_REVIEW`，10 张样图为 `REFBATCH02`，4 张为裁切参考。

停止条件：缺文件、hash 不符、目标路径冲突。输出具体 asset_id，不改名蒙混。

### PREP-B｜角色与服装基线细化

输入：上述素材、用户现有方向反馈、`docs/preproduction/CHARACTER_ASSET_SPEC_V5.md`。

动作：分开判断脸、冠帽/发饰、服装、场景。候选设定板上的文学文案、眼皮类型、身高、影视版本文字都不是机器事实。用户确认的脸部裁片只负责身份；服装另选 stage 引用；不能将一整张含字的设定板直接输入 I2V。

产物：具体 reference_id 的批准证据，必要的 HOME 服装单独参考仍列待制作；缺侧面不伪造“已有侧面批准”。

停止条件：脸型不对、头饰混用、服装阶段不清。先局部修图，不试视频。

### PREP-C｜逐镜创作包

输入：V5 执行计划、角色引用和构图参考。

动作：以 `director_cards_v5.md` 的镜头为工作单位，一镜最多 3 个静帧候选；每张记录引用、文件 hash、缺陷。保持古装、生活场景、自然眼神，不把每镜都做成仙侠海报。EP001 用当前三句台词，新增跨集伏笔不挤进第一集。

产物：LOOKREEL01 十镜关键帧、EP001 二十镜关键帧的候选/批准记录。**已完成镜头设计不等于已经生成这三十张图。**

停止条件：身份/服装/关键肢体硬错误，不以构图和光影得分抵消。

### PREP-D｜离线合同检查和三张小样准备

输入：具体批准的关键帧、具体批准的参考资产、候选 I2V workflow。

动作：运行 `guard` 与 `prepare`；检查实际通往 KSampler、VAEDecode、CreateVideo、SaveVideo 的线路，不能仅检查有一个未使用的 LoadImage。检查资产 hash、出场角色、服装 stage、批准证据绑定、M0/M3 过滤。输出冻结输入和 workflow 的任务包，**不发网络请求**。

产物：`job.json + workflow.json + input.png/jpg`，状态为 `PREPARED_NOT_SUBMITTED`。

小样规则：三张合适的关键帧可先做 T1 局部试验，不必等待另外七张全部完成；完整 LOOKREEL01 交付仍需十镜全部批准。这一条明确修正旧文件“必须十张全过才能试一条”的重复等待，不取消逐资产批准。

### LOCAL-T1｜仅此处开始使用本机 GPU

输入：通过检查的任务包。先在本机重新确认 ComfyUI URL、队列和 RAM/VRAM，不把历史端口/占用当作此刻事实。

动作：先 dry-run，明确执行后用 `submit_prepared.py --execute` 调用已有 probe；一次一镜。每个任务记录提交意图，超时/断线不自动重新 POST，先看 prompt_id 与 history。

产物：原始视频、实际 ffprobe 数据、运行记录。41/49/81 等任何帧数都不能凭文件名猜；以输出为准。

停止条件：连续两次身份漂移、持续内存压力、服务异常、结果状态未知。保留同一批准静帧，不换更大的模型掩盖问题。

### EDIT-E0/E1｜先做可读的片，再增加动态

LOOKREEL01：648 帧/24 fps=27 秒，4 个候选 I2V、6 个静帧处理。

EP001：1440 帧/24 fps=60 秒，6 个候选 I2V、14 个静帧处理。角色正确、故事顺畅之后，再逐镜增加动态，不把“动态比例”当硬 KPI。

音频先用临时画外音和环境声。字幕是时间线草稿，不代表配音已录制。最终输出 1080×1920 是交付画布，不能宣称素材原生 1080P。

### RELEASE｜最终验收

技术检查与人工审美检查分别签字。内部预览不自动获得公开/商业发布资格；模型、音乐、声音、图像引用的使用条件单列为发布待核项目。本轮没有完成这项法律/授权确认。

## 远端已做与本地仍需做

远端可验证：文件存在性、hash、数据合同、时长数学、脚本单元测试、CPU 静态审片序列、缺口报告。

本地仍需验证：实际 ComfyUI API/节点兼容、5B I2V 资源、人物运动稳定性、完整成片渲染、声音与最终画面验收。

人为审美批准不可由脚本或本助手代签。除此之外，不把可在远端完成的编剧、数据检查、素材整理重新推给本地 Agent。
